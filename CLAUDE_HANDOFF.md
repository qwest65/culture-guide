## Критическая проблема схемы

На предыдущих версиях схема получалась визуально плохой.

Была проблема:

- линии строились по GPS-координатам;
- затем появились случайные диагонали;
- пересадки плохо читались;
- схема выглядела как граф/debug visualization.

После этого схема была переведена на порядок станций в маршрутах.

Однако layout всё ещё требует нормальной реализации.

### Требования к новой схеме

Сделать настоящий schematic transit-map layout:

1. Географические координаты НЕ использовать для положения станции на схеме.
2. Положение определяется топологией маршрутов.
3. Каждая линия должна иметь последовательность станций.
4. Общая станция должна быть одним физическим узлом.
5. Пересадка должна быть визуально очевидна.
6. Линии должны использовать горизонтальные/вертикальные сегменты.
7. Допустимы короткие 45° сегменты только если они реально улучшают layout.
8. Не допускать случайных длинных диагоналей.
9. Не допускать наложения названий станций.
10. Схема должна быть читаемой на телефоне 5–7".
11. Станции не должны располагаться в случайных средних координатах только потому, что объект встречается в двух линиях.
12. Для 3 линий и текущих данных Троицка layout должен быть заранее проверяемым и стабильным.

Можно использовать алгоритм:
- сначала выбрать базовую линию;
- расположить её станции равномерно;
- остальные линии привязывать к уже существующим пересадкам;
- новые станции раскладывать вдоль свободных участков;
- после размещения выполнить orthogonal routing;
- выполнить collision avoidance для узлов/подписей.

Не возвращаться к layout на основе lat/lon.

## Почему пользователь жаловался на APK

Пользователь заметил, что размер APK практически не меняется.

Важно:

- размер APK не является надёжным способом определить изменение Kotlin UI;
- до последнего изменения `versionCode` оставался 1;
- сейчас версия должна быть 0.2.0 / versionCode 2;
- CI публикует mutable release `latest`, поэтому важно не путать старый APK с новой сборкой.

### Рекомендуемое изменение CI

Сделать публикацию однозначной:

- APK filename: `CultureGuide-v0.2.0+<short-sha>.apk`;
- отдельный artifact;
- release tag, например `v0.2.0`;
- сохранять также `latest`;
- выводить versionName/versionCode/SHA в build log.

Не удалять текущий `latest`, пока новая сборка не подтверждена.

## Маршрутизация

Текущий `buildRoute()`:

- выбирает ближайший объект к текущей GPS-позиции;
- затем использует greedy nearest-neighbour порядок;
- рисует Polyline между координатами.

Это НЕ настоящий пеший маршрут.

В будущем заменить на routing API.
