# CultureGuide / Культурный маршрут

Android-приложение-путеводитель по памятникам, музеям, архитектуре и другим культурным объектам.

Репозиторий: https://github.com/qwest65/prog

## Текущее состояние

Проект переведён на native Android:

- Kotlin
- Android Gradle Plugin 8.7.2
- Kotlin 2.1.20
- Gradle 8.9
- Java 17
- compileSdk 35 / targetSdk 35 / minSdk 26
- Yandex MapKit Full 4.45.0 (поиск/геокодирование/маршрутизация доступны SDK)
- SQLite для локальных городов, объектов и тематических маршрутов
- GitHub Actions для сборки APK

Стартовые данные сейчас содержат Троицк, Челябинская область, Россия.

## Что уже работает

- Яндекс-карта;
- отображение объектов на карте;
- карточка объекта;
- переход к объекту в Яндекс Картах или браузере;
- GPS/геолокация;
- выбор города через Spinner;
- архитектура City -> Places -> RouteLine -> route_places;
- несколько тематических маршрутов;
- общие объекты между маршрутами определяются как пересадки;
- схематическая карта маршрутов в стиле транспортной схемы;
- построение порядка посещения объектов;
- GitHub Actions собирает debug APK и публикует его как release `latest`.

## Что реализовано в текущем этапе

- поиск по названию, категории и адресу внутри каталога;
- поиск города через Yandex Search API с выбором результата и добавлением координат;
- поиск культурных объектов через Yandex Search API с добавлением найденного объекта в локальный каталог;
- добавление городов с координатами;
- добавление культурных объектов;
- экспорт полного каталога в JSON;
- импорт каталога из JSON через системный файловый picker;
- отображение версии приложения на главном экране;
- горизонтальная панель действий, не исчезающая на узких экранах;
- deterministic schematic layout без использования GPS для координат станций;
- общие станции маршрутов отображаются как единый узел-пересадка;
- GitHub Actions публикует versioned artifact с коротким SHA коммита;
- текущая проверенная сборка: 0.5.0 / versionCode 5;
- MapKit переведён с Lite на Full как подготовка к поиску/геокодированию и маршрутизации.

## Известные проблемы

1. Схему нужно проверить на реальном APK/Nox и при необходимости доработать collision avoidance подписей. Нужен аккуратный алгоритм layout:
   - станции должны идти в порядке маршрута;
   - пересадки должны быть одним узлом;
   - линии должны быть преимущественно горизонтальными/вертикальными;
   - не должно быть случайных диагоналей;
   - подписи/легенда должны оставаться читаемыми на телефоне.

2. Сейчас схема оставлена поверх очень светлой карты для визуального контекста. Следующий UX-шаг — полноценный переключатель «Карта / Схема» с сохранением выбранной линии.

3. Карта маршрута сейчас рисует прямые Polyline между координатами объектов. Это НЕ навигация по улицам. Для полноценного пешего маршрута нужен routing API.

4. Сейчас реальные данные есть только для Троицка. Архитектура БД подготовлена для нескольких городов, но нет загрузчика/поиска/каталога городов мира.

5. Локальный поиск объектов и Yandex Search для поиска городов реализованы. Geosuggest и полноценный поиск объектов в Yandex Search ещё можно расширить.

6. Нет удалённого каталога данных и синхронизации.

7. `latest` сохраняется для быстрого тестирования, а CI теперь дополнительно публикует versioned artifact с versionName/versionCode/SHA.

8. Секрет `MAPKIT_API_KEY` находится только в GitHub Actions secret. Не добавлять его в Git.

## Сборка

Локально:

```bash
gradle assembleDebug
```

Для GitHub Actions должен быть настроен secret:

```
MAPKIT_API_KEY
```

APK:

```
app/build/outputs/apk/debug/
```

## Важно для Claude

Не начинать с переписывания всего проекта.

Сначала:

1. изучить `MainActivity.kt`;
2. проверить Gradle/Manifest/MapKit;
3. собрать проект;
4. проверить текущую схему и UI;
5. исправить конкретные проблемы;
6. после каждого существенного изменения собрать APK;
7. не менять рабочую Яндекс-карту без необходимости.

Не считать размер APK признаком наличия изменений: изменение Kotlin-кода может почти не изменить размер APK. Для идентификации сборки использовать `versionCode`, `versionName` и commit SHA.

Не использовать OpenStreetMap tile server в Android-приложении вместо разрешённого картографического SDK.
